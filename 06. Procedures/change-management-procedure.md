# Change Management Procedure

**Supports:** Control A.8.32

## 1. Purpose
To ensure changes to information systems are assessed, approved, tested, and documented to avoid unintended security impact.

## 2. Procedure
1. Change request submitted with description, risk assessment, rollback plan
2. Risk-based approval: Low-risk changes may be pre-approved (standard changes); Medium/High-risk require Change Advisory Board (CAB) review
3. Change tested in non-production environment where feasible
4. Change scheduled within an approved maintenance window (except emergency changes)
5. Post-implementation review confirms change succeeded without unintended security impact
6. Emergency changes documented retroactively within [24 hours] with CISO sign-off

## 3. Records
Change log maintained with requester, approver, date, and outcome.
