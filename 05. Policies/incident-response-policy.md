# Incident Response Policy

**Supports:** Controls A.5.24, A.5.25, A.5.26, A.5.27, A.6.8

| Document Control | |
|---|---|
| Document Owner | [CISO] |
| Version | 1.0 |
| Review Cycle | Annual |

## 1. Purpose
To ensure information security incidents are detected, reported, assessed, and responded to consistently and in a timely manner.

## 2. Policy Statement
- All employees must report suspected security incidents immediately via [reporting channel] using the Security Incident Form (`07. Templates`)
- Incidents are triaged, classified by severity, and assigned an owner within [1 hour] of report
- A formal Incident Response Procedure (`06. Procedures`) governs detection, containment, eradication, recovery, and lessons learned
- Regulatory/customer notification timelines (e.g., GDPR 72-hour breach notification) are tracked and met
- All incidents are logged in the Incident Log (`08. Records/Incident Logs`) and reviewed post-incident

## 3. Roles
| Role | Responsibility |
|---|---|
| Incident Responder | First response, containment |
| CISO | Escalation decisions, regulatory notification |
| Legal/Comms | External communication, breach notification |

## 4. Testing
Incident response is tested via tabletop exercises at least annually.
